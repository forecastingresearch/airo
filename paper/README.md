# paper/ — figures and numbers for the Auto-ARC paper

Generated by `python3 -m redlines paper` from the tracked `results/*.json`
blobs — the same data the dashboard's JSX renders — so a figure or a quoted
number cannot disagree with the page. Re-run after every `redlines build`;
`tests/test_paper.py` fails until `numbers.tex` is regenerated.

```
python3 -m redlines paper                 # fig/*.pdf (pdflatex-typeset) + numbers.tex
python3 -m redlines paper --font times    # newtx instead of Computer Modern
python3 -m redlines paper --backend agg   # no TeX install: STIX via matplotlib
python3 -m redlines paper --figs g4       # one figure
uv sync --extra paper                     # matplotlib (figures only; numbers.tex is stdlib)
```

## Numbers (`numbers.tex`)

```latex
\input{numbers.tex}
The ensemble median is \rl{g1:catastrophe:general:2030:median}\%
(models span \rl{g1:catastrophe:general:2030:lo}--\rl{g1:catastrophe:general:2030:hi}).
```

An unknown key renders as **??key??** so a stale reference is visible.
Key families (see `redlines/paper/numbers.py::collect` for the full list):

- `run:latest`, `run:dates`, `repeats`, `models:n`, `questions:n`, `cells:n`
- `g1:<qid>:<horizon>:median`, `g1:<qid>:<horizon>:model:<slug>`,
  `g1:<qid>:<horizon>:model:{min,max}` (+ `:label`) — the ends of the across-model spread,
  also as `g1:<qid>:<horizon>:{lo,hi}` (the same range; NOT a confidence interval),
  `g1:<qid>:<horizon>:human:<panel>:<group>` — probabilities in percent;
  `loss:*` rows in death-equivalents (`2.7M`)
- `g1:catastrophe:<cause>:<horizon>:median` for bio, cyber and misalign — legacy aliases for the TOP rung of that cause's incident ladder
  (`g1:catastrophe:cause:rung` / `:label`, ≥1B deaths, about 12% of the
  population), the nearest the instrument comes to a per-cause 10%-of-humanity
  question, but with a deaths-OR-damages outcome; `mortality:run:date` = `run:latest`.
  `g1:catastrophe:ai:<horizon>:median` always means the separately elicited
  10%-of-humanity mortality catastrophe. Use `g2:ladder:ai:1B:<horizon>:median`
  for the AI-container top incident rung; these are distinct questions.
- `g2:audit:{bad,n,rate,coherent}`, `g2:audit:<constraint>:{bad,n}`
- `g3:{tools,sup,bare}:{n,brier,resolution,base,lo:n,lo:pred,lo:obs,market:*,rounds:*}`
- `g4:{rho,rhoClean,models:n,modelsClean:n,rows:n,base,eci:min,eci:max}`,
  `g4:model:<slug>:{eci,bss,brier,n,meanPred,meanObs,sims}`, `g4:best:*`, `g4:topEci:*`,
  `g4:excluded:list`, `g4:oneSim:list`
- `cond:<qid>:<horizon>:baseline`,
  `cond:<qid>:<horizon>:<condition>:{ratio,cut,lowered,raised}`
  (`cut` = percent reduction, `100·(1−ratio)`);
  `cond:<qid>:<horizon>:<condition>:median` — the actual ensemble median of
  conditional forecasts (`pMedian` in the blob), for absolute probabilities
  or loss levels in prose; `:median:priced` — the percent reduction from that
  conditional median to the unconditional median, `100·(1−baseline/median)`
  (omitted when the conditional median is zero). These differ from `:level`
  and `:priced`, which are derived from the median of per-model ratios;
  `cond:<qid>:<horizon>:<condition>:{lo,hi}` (+ `:label`) — the across-model
  range of the ratio, i.e. the dots on the figure, NOT a confidence interval;
  `cond:<qid>:<horizon>:<condition>:level` — the conditioned world in the
  baseline's units (ensemble ratio × ensemble baseline, so a derived figure,
  not a median of per-model levels);
  `cond:<qid>:<horizon>:<condition>:priced` — the cut the unconditional makes
  *from* that world, `100·(1−1/ratio)`. For `sq` (status quo, no new AI
  policy) `level` is the un-mitigated risk and `priced` is the mitigation the
  models price in. No confidence intervals anywhere: the instrument is elicited
  once per run (2026-09-02), so re-elicitation noise is not a quantity we
  publish; every `lo`/`hi` is the range across the panel's models.

- `cap:*` — the capability tab's default variant, same cell keys as `cond:*`
  (`cap:<qid>:<horizon>:<condition>:{ratio,…,level,priced,…}` with conditions
  `eci_p25`, `eci_p50`, `eci_p75` (+ `eci_p10`, `eci_p90` once a v4 run lands)),
  plus `cap:{variant,runs,protocol,conditions:n,models:n,models:list,target,target:months}`,
  the levels `cap:eci:<condition>` (ensemble median of the model's own percentile),
  `cap:eci:{latest,latest:date,latest:model,csvDate,trend:rate}`,
  `cap:eci:ensemble:<pct>`, `cap:eci:trend:<pct>` (the metr_graph trend at the
  target date), `cap:eci:model:<slug>:<pct>`, `cap:eci:leap:<group>:<year>:<pct>`
  (LEAP Wave 5 human forecasts of the same index), and the steepness
  `cap:<qid>:<horizon>:{iqr:ratio,iqr:points,perPoint:pct}` — p75 ÷ p25 ratio,
  the ECI points between them, compound percent change per point; and
  `cap:<qid>:<horizon>:tails:{ratio,points}` — the same for p90 ÷ p10.
- `coh:ladder:{control,arm:b,arm:c,arm:b-all}:{ladders,coherent,coherent:pct,pairs,bad,bad:pct,cross:pairs,cross:bad,cross:bad:pct}`,
  `coh:ladder:arm:<arm>:fisherP`, `coh:ladder:control:runs` — the joint-elicitation
  experiment on the retired severity ladder (`docs/coherence-experiment.md` §1–2, §6b):
  control = one call per rung (two runs pooled for the within-ladder figures; the
  cross-cause figure is the second run alone, as in §6b), arm b = one call per cause,
  arm c = b plus the stated constraint, arm b-all = one call per model. `bad` counts
  adjacent rung pairs where P rose with severity; `cross` counts a specific cause
  forecast above the all-cause rung that contains it.
- `coh:chain:{sep,joint}:{chains,coherent,coherent:pct,pairs,bad,bad:pct,brier}`,
  `coh:chain:{cells,models:n,models:list,brier:delta}`,
  `coh:chain:byChain:{n,better,worse,tied,medianDelta,p}` — the resolvable test on
  FreeCiv nested chains (§3): 60 model × chain observations, Wilcoxon on the
  per-chain mean Brier difference. Source blob `results/coherence_experiment.json`,
  rebuilt by `python3 code/coherence_blob.py` (`--check` reports staleness).
- `prompt:*` — the published instrument's prompt, for the appendix, built by the
  runner's own builder (`code/run_unified.py`, `data/combined_conditions.json`, no
  model called) with today = `run:latest`, so the rolling-horizon and ECI target
  dates are fixed. Counts: `prompt:{protocol,today,questions:n,cells:n,horizons:n,
  horizons:list,conditions:n,conditions:policy:n,conditions:capability:n,
  probabilities:n,chars,research:min,rounds:max}`. Text, one line each, breaks as `\newline`/`\par`: `prompt:system`, `prompt:user:{head,tail}`,
  `prompt:question:{catastrophe:general,catastrophe:ai,disempowerment,ladder:ai:100}`,
  `prompt:shared` (the criteria block every incident question shares),
  `prompt:conditions:{preamble,policy:instruction,capability:instruction}`,
  `prompt:condition:{sq,eci_p50}`. Typeset each inside a monospace, ragged block:

  ```latex
  \newcommand{\rlprompt}[1]{\begin{quote}\small\ttfamily\raggedright\noindent\rl{#1}\par\end{quote}}
  \rlprompt{prompt:system}
  ```

Formatting is fixed in `numbers.py`: probabilities two decimals below 1%, one
above; ratios and skill scores two decimals; correlations signed.

### Visual review during manuscript edits

Visual PDF review is part of manuscript editing (added September 10, 2026).
Compile the manuscript and inspect rendered pages, including figures at their
actual page size. Check overlapping labels, clipping, captions, page breaks,
footnotes, and long bibliography URLs. Reinspect affected pages after repairs;
a successful LaTeX build alone does not establish that the layout is readable.
When syncing `numbers.tex`, refresh the corresponding generated figures and
check that their baselines, model rosters, and conditions agree with the prose.
